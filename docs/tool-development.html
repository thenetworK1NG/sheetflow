Tool Development Guide

Sheetflow Tools No build step Vanilla JS

Sheetflow tools are self-contained JavaScript files that extend the spreadsheet organizer without modifying the base app. A tool handles its own UI, state, and lifecycle. The base app provides the window.sf SDK namespace, injection slots, and a tool registry — everything else is up to you.

Overview

A Sheetflow tool is a single .sf file containing JSON metadata and a JavaScript code string. When installed, the code runs once via new Function(code)(), registers the tool with the base app, and the base app calls your activate() / deactivate() lifecycle methods as the user opens and closes it.

Your tool is fully self-contained. You inject your own buttons, panels, sidebar widgets, and state. The base app provides:

  • window.sf SDK — event bus, data API, modal system, sidebar/topbar APIs, keyboard shortcuts, utility wrappers, and read-only access to refs & state
  • Injection slots — five designated empty containers where your UI goes
  • registerTool() — registers your tool in the Tools panel
  • CSS design system — pre-built classes and custom properties for a consistent look

Quick Start

The fastest way to create a tool. Save this as hello-world.sf and install it through the Tools panel.

// Code string inside your .sf file
var style = document.createElement("style");
style.textContent =
  '.hw-panel{margin:18px 0;padding:16px 20px;border:1px solid var(--line);border-radius:var(--radius);background:var(--panel)}';
document.head.appendChild(style);

registerTool({
  id: "hello-world",
  name: "Hello World",
  icon: "\uD83D\uDC4B",
  description: "A minimal example tool.",

  activate: function() {
    this._panel = document.createElement("div");
    this._panel.className = "hw-panel";
    this._panel.innerHTML =
      '<h3>Hello from your tool!</h3>' +
      '<p>This panel is injected into the tool panels slot.</p>';
    document.getElementById("toolPanelsSlot").appendChild(this._panel);
  },

  deactivate: function() {
    if (this._panel) { this._panel.remove(); this._panel = null; }
  }
});

Wrap it in the .sf format:

{
  "format": "sheetflow-tool",
  "version": 1,
  "tool": {
    "id": "hello-world",
    "name": "Hello World",
    "icon": "\uD83D\uDC4B",
    "description": "A minimal example tool.",
    "author": "Your Name",
    "version": "1.0.0",
    "code": "... your JavaScript code as a string ..."
  }
}

1

Load the spreadsheet organizer in your browser.

2
Click Tools in the top bar

Opens the Tools panel where you manage installed tools.

3

The .sf File Format

An .sf file is a JSON file with the following structure:

FieldTypeDescription
formatstringMust be "sheetflow-tool"
versionnumberFormat version. Currently 1.
toolobjectThe tool definition (see below).

Tool object fields

FieldTypeRequiredDescription
idstringYesUnique identifier. Use lowercase-kebab-case.
namestringYesDisplay name shown in the Tools panel.
iconstringNoEmoji or symbol. Defaults to ⚙.
descriptionstringNoShort description shown in the Tools panel.
authorstringNoYour name or organization.
versionstringNoSemantic version string (e.g. "1.0.0").
codestringYesJavaScript code that runs once on load. Must call registerTool().

Tool Structure

A tool's code string runs once when installed (or on page load for already-installed tools). It must call registerTool() with an object containing your tool's metadata and lifecycle methods.

// 1. Inject your CSS (optional, recommended)
var style = document.createElement("style");
style.textContent = ".my-tool-panel { /* ... */ }";
document.head.appendChild(style);

// 2. Register the tool
registerTool({
  id: "my-tool",
  name: "My Tool",
  icon: "\uD83D\uDD27",
  description: "What it does.",

  // State (your tool owns this)
  _panel: null,
  _listeners: [],

  // Called when user opens the tool
  activate: function() {
    // Create your UI and inject into a slot
    // Subscribe to events, read data via sf.*, etc.
  },

  // Called when user closes the tool or switches to another
  deactivate: function() {
    // Remove your UI, detach event listeners, clear timers
  }
});
Important: Your code runs once. The activate()/deactivate() cycle can happen many times. Always clean up in deactivate() — remove DOM elements, unsubscribe event listeners, clear timers, and unregister keyboard shortcuts.

The sf Namespace

The base app exposes window.sf as the primary interface for tool developers. It provides a unified API for events, data, UI, and utilities. All tool code should use sf.* instead of calling base app globals directly.

📦

Event Bus

The event bus lets tools subscribe to app lifecycle events and communicate with each other. Use sf.on() to listen and sf.emit() to broadcast.

MethodSignatureDescription
sf.on()sf.on(eventName, callback)Subscribe to an event. Callback receives event data. Returns nothing.
sf.off()sf.off(eventName, callback)Unsubscribe a specific callback.
sf.emit()sf.emit(eventName, data)Broadcast an event to all subscribers. Pass arbitrary data.
sf.once()sf.once(eventName, callback)Subscribe, then auto-unsubscribe after the first call.

Built-in Events

EventDataWhen
sheet:loaded{ fileName: string }A spreadsheet file finishes loading
sheet:cleared{}Workspace is cleared
sheet:changed{ sheetName: string }User switches between worksheets
tool:activated{ toolId: string }A tool is activated
tool:deactivated{ toolId: string }A tool is deactivated
data:modified{ type, rowId, ... }Row data is modified (cell edit, insert, delete)
row:hidden{ id, row }A row is hidden
row:shown{ id, row }A hidden row is shown
selection:changed{ selectedIds: Set }Row selection changes

Subscribe to sheet load

registerTool({
  id: "load-watcher",
  name: "Load Watcher",
  icon: "\uD83D\uDC41",

  activate: function() {
    var self = this;
    this._onLoad = function(data) {
      sf.showToast("Loaded: " + data.fileName, "success");
    };
    sf.on("sheet:loaded", this._onLoad);
  },

  deactivate: function() {
    sf.off("sheet:loaded", this._onLoad);
  }
});

Emit a custom event

// In Tool A: emit a custom event
sf.emit("my-tool:dataReady", { count: 42 });

// In Tool B: listen for it
sf.on("my-tool:dataReady", function(data) {
  sf.showToast("Tool A found " + data.count + " items");
});

Listen once

// Fires only on the first data modification after activation
sf.once("data:modified", function(data) {
  sf.showToast("First edit detected: row " + data.rowId);
});

Track selection changes

registerTool({
  id: "selection-tracker",
  name: "Selection Tracker",
  icon: "\u2705",

  activate: function() {
    var self = this;
    this._onSelection = function(data) {
      var count = data.selectedIds.size;
      if (count > 0) {
        sf.showToast(count + " row" + (count > 1 ? "s" : "") + " selected");
      }
    };
    sf.on("selection:changed", this._onSelection);
  },

  deactivate: function() {
    sf.off("selection:changed", this._onSelection);
  }
});

Data API

Read and modify spreadsheet data through the sf namespace. All methods operate on the current active sheet.

Reading Data

MethodReturnsDescription
sf.getVisibleRows()Row[]Rows that are not hidden
sf.getAllRows()Row[]All rows, including hidden ones
sf.findRows(colIndex, filterFn)Row[]Filter rows. filterFn(row, colIndex) returns boolean
sf.getColumnData(colIndex)any[]All raw values in a column
sf.getColumnStats(colIndex)object{ count, numeric, min, max, sum, avg }
sf.getSelectedRows()Row[]Currently selected row objects
sf.rowById(id)Row | undefinedFind a single row by its ID

Row Object Shape

{
  id: string,           // Unique row identifier
  values: any[],        // Cell values, indexed by column
  searchText: string,   // Flattened lowercase text for search
  emptyColumns: bool[], // Which columns are empty
  sourceIndex: number,  // Original position in the source sheet
  sourceRowNumber: number, // 1-based row number in spreadsheet
  blank: boolean,       // True if all values are empty
  hidden: boolean       // True if row is hidden
}

Writing Data

MethodReturnsDescription
sf.hideRow(id)voidHide a row by ID. Emits row:hidden.
sf.showRow(id)voidShow a hidden row. Emits row:shown.
sf.toggleRowVisibility(id)voidToggle a row's hidden state.
sf.setCellValue(rowId, colIndex, value)booleanEdit a cell. Returns true on success. Emits data:modified.
sf.insertRow(afterIndex, values)Row | nullInsert a row after the given index. Emits data:modified.
sf.deleteRow(id)booleanPermanently delete a row. Emits data:modified.
sf.selectAllRows()voidSelect all rows. Emits selection:changed.
sf.deselectAllRows()voidClear selection. Emits selection:changed.
Always call sf.refresh() after modifying data (hide, show, insert, delete, cell edit) to re-render the base app's table, stats, and page controls.

Get column statistics

registerTool({
  id: "col-stats",
  name: "Column Stats",
  icon: "\uD83D\uDCCA",

  activate: function() {
    var sheet = sf.currentSheet();
    if (!sheet) { sf.showToast("No data loaded.", "error"); return; }

    var qtyCol = sheet.quantityColumn;
    if (qtyCol === null) { sf.showToast("No quantity column detected.", "error"); return; }

    var stats = sf.getColumnStats(qtyCol);
    sf.showToast(
      "Qty: " + stats.numeric + " numeric rows, " +
      "sum=" + sf.formatNumber(stats.sum) + ", " +
      "avg=" + sf.formatNumber(Math.round(stats.avg * 100) / 100)
    );
  }
});

Find and hide rows matching a filter

registerTool({
  id: "blank-hider",
  name: "Hide Blank Rows",
  icon: "\uD83D\uDD76",

  activate: function() {
    var rows = sf.findRows(0, function(row) {
      var val = sf.valueToString(row.values[0]);
      return !val.trim();
    });
    rows.forEach(function(row) { sf.hideRow(row.id); });
    sf.refresh();
    sf.showToast("Hidden " + rows.length + " blank rows.", "success");
  }
});

Read all column values

var sheet = sf.currentSheet();
if (sheet) {
  var names = sf.getColumnData(0);
  var unique = [];
  names.forEach(function(v) {
    var s = sf.valueToString(v);
    if (s && unique.indexOf(s) === -1) unique.push(s);
  });
  sf.showToast(unique.length + " unique values in column 1");
}

Insert and delete rows

// Insert a new row after row index 2
var newRow = sf.insertRow(2, ["Widget A", "Warehouse 1", "100"]);
if (newRow) {
  sf.showToast("Inserted row: " + newRow.id, "success");
}

// Delete it
sf.deleteRow(newRow.id);
sf.refresh();

Edit a cell value

var sheet = sf.currentSheet();
if (sheet && sheet.rows.length > 0) {
  var row = sheet.rows[0];
  sf.setCellValue(row.id, 1, "Updated Value");
  sf.refresh();
  sf.showToast("Cell updated.", "success");
}

Add a sidebar section

Add a topbar button

registerTool({
  id: "export-csv",
  name: "CSV Export",
  icon: "\uD83D\uDCE4",

  activate: function() {
    var self = this;
    sf.addTopbarButton({
      id: "export-csv-btn",
      label: "Export CSV",
      icon: "\uD83D\uDCE4",
      onClick: function() {
        var sheet = sf.currentSheet();
        if (!sheet) { sf.showToast("No data.", "error"); return; }

        var header = sheet.headers.join(",");
        var lines = sf.getVisibleRows().map(function(r) {
          return r.values.map(function(v) {
            return '"' + sf.valueToString(v).replace(/"/g, '""') + '"';
          }).join(",");
        });
        sf.downloadText(header + "\n" + lines.join("\n"), "export.csv", "text/csv");
        sf.showToast("CSV exported.", "success");
      }
    });
  },

  deactivate: function() {
    sf.removeTopbarButton("export-csv-btn");
  }
});

Add a topbar dropdown

registerTool({
  id: "sort-tool",
  name: "Sort Tool",
  icon: "\uD83D\uDD03",

  activate: function() {
    sf.addTopbarDropdown({
      id: "sort-dropdown",
      label: "Sort",
      items: [
        { label: "Sort A\u2192Z", icon: "\u2191", onClick: function() { sortColumn(0, "asc"); } },
        { label: "Sort Z\u2192A", icon: "\u2193", onClick: function() { sortColumn(0, "desc"); } },
        { divider: true },
        { label: "Sort by Quantity", icon: "\uD83D\uDCCA", onClick: function() { sortColumn(3, "desc"); } }
      ]
    });
  },

  deactivate: function() {
    sf.removeTopbarDropdown("sort-dropdown");
  }
});

function sortColumn(colIndex, dir) {
  var sheet = sf.currentSheet();
  if (!sheet) return;
  sheet.rows.sort(function(a, b) {
    var va = sf.valueToString(a.values[colIndex]);
    var vb = sf.valueToString(b.values[colIndex]);
    var cmp = va.localeCompare(vb, undefined, { numeric: true });
    return dir === "desc" ? -cmp : cmp;
  });
  sf.refresh();
  sf.showToast("Sorted by column " + (colIndex + 1), "success");
}

Keyboard Shortcuts

Register global keyboard shortcuts that work when your tool is active. The SDK intercepts keystrokes before the base app's handler.

MethodSignatureDescription
sf.registerShortcut()sf.registerShortcut(combo, callback, description)Register a keyboard shortcut.
sf.unregisterShortcut()sf.unregisterShortcut(combo)Remove a keyboard shortcut.

Combo format: Modifiers + key, joined by +. Case-insensitive. Supported modifiers: Ctrl, Shift, Alt, Meta (Cmd on Mac).

Register shortcuts

registerTool({
  id: "shortcut-demo",
  name: "Shortcut Demo",
  icon: "\u2328\uFE0F",

  activate: function() {
    var self = this;

    sf.registerShortcut("Ctrl+Shift+F", function() {
      sf.showToast("Search triggered!", "success");
    }, "Open search");

    sf.registerShortcut("Ctrl+Shift+D", function() {
      var rows = sf.getVisibleRows();
      sf.showToast(rows.length + " visible rows", "success");
    }, "Show row count");

    sf.registerShortcut("Escape", function() {
      // Custom escape behavior
      sf.showToast("Escape pressed", "");
    }, "Custom escape");
  },

  deactivate: function() {
    sf.unregisterShortcut("Ctrl+Shift+F");
    sf.unregisterShortcut("Ctrl+Shift+D");
    sf.unregisterShortcut("Escape");
  }
});
Always unregister shortcuts in deactivate(). Otherwise they persist after the tool is closed and may conflict with other tools or the base app.

Injection Slots

Sheetflow provides five designated empty containers where tools inject their UI. Use document.getElementById() to find them.

🔘
toolActionSlot
Location: Topbar, far left of the action area.
Use for: Primary tool action buttons (export, run, process).
Layout: Flex row. Buttons appear inline at the start of the topbar actions.
Preferred API: sf.addTopbarButton() manages this slot automatically.
📋
toolDropdownSlot
Location: Topbar, after the action slot.
Use for: Dropdown menus with multiple options.
Layout: Flex row. Dropdowns appear after any action buttons.
Preferred API: sf.addTopbarDropdown() manages this slot automatically.
⚙️
toolButtonsSlot
Location: Topbar, between the dropdown slot and the Tools button.
Use for: Additional toggle buttons, status indicators, secondary actions.
Layout: Flex row. Buttons appear inline in the topbar.
📐
toolPanelsSlot
Location: Between the topbar and the workspace section.
Use for: Tool control panels, forms, configuration UIs, rule editors, filter bars.
Layout: Block. Panels appear stacked vertically above the workspace.
📎
toolSidebarSlot
Location: Left sidebar, below the file import zone.
Use for: Sidebar settings, file-specific tool controls, compact widgets, live stats.
Layout: Block. Content appears in the sidebar column.
Preferred API: sf.addSidebarSection() manages this slot automatically. 
// Direct slot injection (for toolButtonsSlot and toolPanelsSlot)
var btnSlot = document.getElementById("toolButtonsSlot");
var btn = document.createElement("button");
btn.className = "button button-ghost button-small";
btn.textContent = "My Action";
btn.addEventListener("click", doSomething);
btnSlot.appendChild(btn);

// Panel injection
var panelSlot = document.getElementById("toolPanelsSlot");
var panel = document.createElement("div");
panel.innerHTML = "...";
panelSlot.appendChild(panel);

// For action buttons, use sf.addTopbarButton() instead (auto-manages toolActionSlot)
// For dropdowns, use sf.addTopbarDropdown() instead (auto-manages toolDropdownSlot)
// For sidebar, use sf.addSidebarSection() instead (auto-manages toolSidebarSlot)
Prefix your IDs. All element IDs your tool creates should be prefixed with your tool's ID (e.g. myTool-submitButton) to avoid collisions with other tools or the base app.

registerTool()

Global function provided by the base app. Call it once in your tool's code.

registerTool({
  id: string,          // Required. Unique tool ID (lowercase-kebab-case).
  name: string,        // Required. Display name.
  icon: string,        // Optional. Emoji/symbol. Default: ⚙
  description: string, // Optional. Short description.
  activate: function,  // Optional. Called when tool is opened.
  deactivate: function // Optional. Called when tool is closed.
});

The tool appears in the Tools panel automatically. Users can toggle it on or off from there. You can also store custom properties on the tool object — they persist across activate/deactivate cycles.

Lifecycle

PhaseWhenWhat to do
code runs App loads or tool is installed Inject CSS into document.head, call registerTool(). Do NOT create UI yet.
activate() User toggles tool on in Tools panel Create UI, inject into slots or use sf.* APIs, subscribe to events, read data, register shortcuts.
deactivate() User toggles tool off or opens another tool Remove UI from slots, unsubscribe events, unregister shortcuts, clear intervals/timeouts, reset state.
activate() can be called multiple times. If a user closes and reopens your tool, activate() runs again. Make sure your code is idempotent — calling it twice without deactivate() in between should not create duplicate UI.

Full lifecycle example

registerTool({
  id: "lifecycle-demo",
  name: "Lifecycle Demo",
  icon: "\uD83D\uDD04",

  _panel: null,
  _onData: null,
  _timer: null,

  activate: function() {
    var self = this;

    // Inject panel
    this._panel = document.createElement("div");
    this._panel.style.cssText = "margin:18px 0;padding:16px 20px;border:1px solid var(--line);border-radius:var(--radius);background:var(--panel)";
    this._panel.innerHTML = '<h3>Lifecycle Demo</h3><p id="ld-count">Counting...</p>';
    document.getElementById("toolPanelsSlot").appendChild(this._panel);

    // Subscribe to events
    this._onData = function() { self._updateCount(); };
    sf.on("data:modified", this._onData);

    // Start polling
    this._timer = setInterval(function() { self._updateCount(); }, 3000);

    // Register a shortcut
    sf.registerShortcut("Ctrl+Shift+L", function() {
      sf.showToast("Lifecycle demo is active!");

    // Unsubscribe
    if (this._onData) { sf.off("data:modified", this._onData); this._onData = null; }

    // Stop polling
    if (this._timer) { clearInterval(this._timer); this._timer = null; }

    // Unregister shortcut
    sf.unregisterShortcut("Ctrl+Shift+L");
  },

    var contentEl = this._panel.querySelector("#dv-results-content");
    if (resultsEl) resultsEl.style.display = "block";
    if (contentEl) {
      contentEl.innerHTML =
        '<div class="sf-row" style="gap:16px;font-size:13px">' +
        '  <div><span style="color:var(--red);font-weight:700">' + errors + '</span> <span class="sf-text-muted">errors</span></div>' +
        '  <div><span style="color:var(--mint);font-weight:700">' + passed + '</span> <span class="sf-text-muted">passed</span></div>' +
        '</div>';
    }

    this._updateSidebar(errors, passed);
    sf.showToast("Validation: " + errors + " errors, " + passed + " passed.", errors > 0 ? "error" : "success");
  },

  _clearResults: function() {
    var resultsEl = this._panel ? this._panel.querySelector("#dv-results") : null;
    if (resultsEl) resultsEl.style.display = "none";
    this._updateSidebar();
  },

  _updateSidebar: function(errors, passed) {
    var r = document.getElementById("dv-s-rules");
    var e = document.getElementById("dv-s-errors");
    var p = document.getElementById("dv-s-passed");
    if (r) r.textContent = this._rules.length;
    if (e) e.textContent = errors || 0;
    if (p) p.textContent = passed || 0;
  }
});

Clash Detection System

Sheetflow includes a built-in clash detection system that scans tools for common conflicts before installation and warns about potential issues when tools are activated together.

What Gets Checked on Install
Your tool's code is scanned for forbidden patterns before registration:
  • window.refresh = — Must use chainRefresh() / unchainRefresh()
  • window.renderTable = — Must use chainRefresh() hook instead
  • eval() — Blocked for security
  • document.write() — Blocked for security
  • document.cookie = — Warned against
  • Overwriting base app function names (refresh, renderTable, etc.) — Blocked
  • Using unprefixed element IDs that clash with the base app (50+ known IDs checked)
What Gets Checked on Activation
When you open a tool, the system checks for clashes with other active tools:
  • Render override clash: Both tools replace tableHead.innerHTML / tableBody.innerHTML — the last registered hook wins
  • Event listener overload: Both tools add many addEventListener calls (>3 each) to the same elements
Warnings appear in the browser console and as badges in the Tools panel.
How to Avoid Clashes
  1. Prefix all IDs: Use yourToolId-elementName for every getElementById and generated id= attribute
  2. Use the sf.* API: Topbar, sidebar, and modal APIs handle their own DOM management and won't clash
  3. Namespace your state: Store tool state on this inside registerTool(), not in global variables
  4. Clean up listeners: Store event references and remove them in deactivate(); use sf.on()/sf.off() for app events
  5. Don't override globals: Never redefine refresh, renderTable, or other base functions

Best Practices

Use the sf.* API over direct DOM manipulation
The SDK provides sf.addTopbarButton(), sf.addTopbarDropdown(), sf.addSidebarSection(), sf.openModal(), and sf.registerShortcut(). These manage injection and cleanup automatically, reducing boilerplate and preventing clashes.
Always prefix element IDs
If you create elements with IDs, use your tool's ID as a prefix: dv-validate, cr-color, fr-findInput. This prevents collisions with other tools and the base app.
Clean up in deactivate()
Remove all DOM elements you created, unsubscribe event listeners (both sf.on() and native), clear intervals/timeouts, unregister keyboard shortcuts, and reset your state. The user may open your tool multiple times.
Make activate() idempotent
Check if elements already exist before creating them. If activate() is called twice without deactivate() in between, don't duplicate UI. The sf.* topbar/sidebar APIs handle this automatically by replacing existing elements with the same ID.
Use the design system classes
Use .sf-card, .sf-kicker, .sf-badge, .sf-form-row, .sf-row, .sf-divider, and button classes like .button-primary for a consistent look. Use CSS custom properties like var(--line), var(--muted), etc. instead of hardcoded colors.
Call sf.refresh() after data changes
If your tool modifies spreadsheet data (row values, hidden state, inserts, deletes), call sf.refresh() to re-render the base app's table, stats, and page controls.
Keep your tool self-contained
All your CSS, HTML generation, state, and logic live in your tool's code string. Don't assume any particular other tool is installed. Don't depend on other tools' globals. Communicate through the event bus if needed.
Use the event bus for cross-tool communication
Don't call other tools' functions directly. Emit and listen for custom events via sf.emit() and sf.on(). This keeps tools decoupled and prevents hard dependencies.

Troubleshooting

ProblemFix
Tool doesn't appear in the list Make sure your code calls registerTool() and the .sf file has valid JSON with "format": "sheetflow-tool".
"Tool code error" on install Open the browser console (F12) to see the syntax error in your code. Fix it, re-export the .sf file.
"Tool failed security scan" on install Open the browser console to see which pattern was blocked. Common causes: eval(), window.refresh =, using base app element IDs without prefixing.
Button doesn't appear in top bar Use sf.addTopbarButton() or ensure you're appending to toolActionSlot / toolButtonsSlot inside activate().
Panel doesn't show above workspace Use document.getElementById("toolPanelsSlot"). Make sure activate() is being called (check the Tools panel).
UI stays after closing tool You're not cleaning up in deactivate(). Remove all DOM elements you created and call sf.removeTopbarButton() / sf.removeTopbarDropdown() / sf.removeSidebarSection().
Tool warning badges in Tools panel Your tool has potential clashes with another installed tool. Hover the badge to see details. Both tools will still work, but rendering may conflict.
Keyboard shortcut doesn't fire Make sure you registered it with sf.registerShortcut(). Check the combo format: use Ctrl+Shift+F (not Control+Shift+KeyF). Make sure the shortcut is registered (you may need to call registration inside activate()).
sf.currentSheet() returns null No data is loaded. Check sf.state.fileName first, or listen for sf.on("sheet:loaded", ...) before accessing sheet data.
Modal doesn't open Check the console for errors. Ensure your sf.openModal() options are correct. The content parameter accepts an HTML string or a DOM element.
Null reference errors Wrap DOM access in null checks. Elements may not exist if no sheet is loaded. Use sf.currentSheet() before accessing sheet data, and check element existence before reading properties.
Data changes don't reflect in the table You forgot to call sf.refresh() after modifying data. The base app only re-renders when told to.
